Intro

Sampling without
giving the sample away.

Discrete Gaussian sampling is a small operation with an unusually large security burden. The distribution must be right, the implementation must be fast, and its physical behavior must not reveal the result.

Motivation

Why the sampler matters

Seven constraints shape the problem.

  1. The target

    Sample a discrete Gaussian

    We want to sample from ℤ according to a distribution shaped like p(x) = exp(−x² / 2σ²) for some width σ.

  2. The application

    A building block for PQC

    Gaussian sampling is useful across post-quantum schemes and algorithms—for example, when generating error vectors for ML-KEMs.

  3. The threat

    The sample must remain private

    The procedure should not leak information about what was sampled through timing, power consumption, or other side channels.

  4. Example 01

    Control flow can reveal the sign

    If sampling from ℤ⁺ takes fewer branches or less processing than sampling from ℤ⁻, an attacker may learn whether the result is positive or negative.

  5. The baseline

    Constant-time execution

    Addressing timing and control-flow leakage means designing code whose execution time does not depend on secret sampled values.

  6. Example 02

    Constant time is not the finish line

    Even constant-time code may leak physically: placing 0000 in an output register can consume different power than placing 1111 in that same register.

  7. The challenge

    Careful, secure, and still fast

    Sampling needs to be engineered with exceptional care while remaining efficient enough for practical cryptographic systems.
