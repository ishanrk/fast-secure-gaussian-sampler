Fast Secure
Gaussian Sampling

A research implementation of Maskaglia

This project treats discrete Gaussian sampling as a small, inspectable cryptographic component. The first checkpoint establishes an unmasked correctness base for later bitsliced, masked, and architecture-specific implementations.

Research status: this code is not production cryptography and is not side-channel secure. The current floating sampler is an approximate, variable-time diagnostic; the masked backend and scheme adapters remain disabled.

The transform under study

Write t for a center bit and c = t/2. Maskaglia begins with the discrete-Laplace proposal qc(z) ∝ 2−|z−c|. For c = 0 the duplicate negative encoding of zero is removed; for c = 1/2 the two signs map a geometric draw k to −k and k + 1.

With rational scale s, rejection uses the exponent e(z) = (|z−c|/s − s/2)². Checkpoint 1 computes this exponent as a checked, reduced rational and tests the kernel identity behind the transform. Its final Bernoulli decision uses exp2l() only as a convenient diagnostic oracle, so the complete sampled distribution is not yet certified.

What checkpoint 1 implements

  • Exact buffered bit stream Caller-injected, exact-fill randomness; little-endian, least-significant-bit-first consumption; sticky source and bound errors.
  • Geometric primitive Counts zero bits before the first one, with a word-level ctz fast path and a public maximum bound.
  • Two Laplace proposals Scalar proposal recipes for the integer and half-integer centers c = 0 and c = 1/2, with errors instead of clipped over-bound outputs.
  • Rational rejection exponent Checked 64-bit arithmetic, explicit overflow errors, and a reduced fraction suitable for differential testing.
  • Diagnostic scalar sampler An approximate, variable-time floating implementation for correctness experiments and statistical tests.
  • 32 × 16 bitslice packing A portable SWAR transpose mapping bit b of lane i to bit i of plane b.

The deterministic test and build harness covers bit ordering, failure propagation, proposal fixtures, the exact kernel identity, overflow handling, mapping, the full bitslice basis, sanitizer runs, and approximate distribution moments.

gmax and tries are public failure bounds. An over-bound call returns no sample; silently retrying would condition the distribution on success. A certified total failure and tail analysis is therefore still roadmap work.

A boundary built for later masking

The core owns sampling; cryptographic-scheme adapters depend on that core, never the reverse. No heap allocation, hidden random source, or native-architecture flag is required by the portable build. The caller supplies an RNG callback that either fills the entire request or fails.

Scalar reference functions may return ordinary integers because they are explicitly unmasked. A future masked interface must retain all 32 lanes as Boolean-share bit planes through the consuming scheme instead of unmasking samples at the API boundary. Sampling coins and fresh masking randomness will use separate contexts.

Security claims stop at the evidence

The current checkpoint is a correctness and measurement base. It makes no constant-time, probing-security, PINI, power, electromagnetic, or production-parameter claim. Ordinary libm and the finite uniform conversion used by the diagnostic path have no portable certified error bound.

The masked capability flag is zero, and enabling the masked backend is intentionally a compile-time error. This prevents an unmasked fallback from being mistaken for protection. A security claim will require the paper-faithful gadgets, their fresh-randomness schedule, optimized assembly inspection, and leakage evaluation on each target.

See the project’s security status for the precise claims made and not made by this checkpoint.

The path from reference to masked sampler

  1. Regenerate and pin the paper’s parameter data, then add a certified MPFR interval oracle.
  2. Implement the exact finite proxy and integer Bernoulli path.
  3. Build paper-faithful SecAND, SecEq, SecGeom, and SecDLX gadgets with gate and randomness counters.
  4. Use a fixed public batching schedule and oblivious movement for accepted lanes.
  5. Specialize share counts, inspect compiler output, and evaluate portable, AVX2, Cortex-M4, and RV32 backends.
  6. Integrate only through a share-aware consumer boundary.

The detailed sequence and completion criteria are maintained in the project roadmap.

HAWK is a research benchmark, not a deployment target

The scalar reference implements and tests the representation map x = 2z − t used to move a sample centered at t/2 into HAWK’s parity coset. The HAWK adapter itself is disabled, and the core has no HAWK dependency.

HAWK was withdrawn from NIST’s additional-signature process on July 29, 2026 following a newly reported key-recovery attack. It remains here to reproduce and evaluate the Maskaglia paper, not to support a live standardization or deployment claim. The rational s = 3/2 used in checkpoint tests is a mathematical fixture, not a production HAWK parameter.
